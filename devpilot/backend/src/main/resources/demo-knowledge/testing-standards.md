# 测试规范

## 用例设计要求

每个已修复的 P0/P1 故障必须沉淀回归用例，用例标题描述"什么条件下应有什么行为"，不写实现细节。优先级定义：P0 资损或不可用，P1 主流程受损，P2 边界场景，P3 体验问题。

## 回归范围

故障修复的回归用例至少覆盖三条路径：正常路径、触发故障的路径、以及相邻的边界路径（例如修复了空指针，必须同时覆盖"有券""无券""券服务降级"三种输入）。

## 外部依赖的处理

涉及远程服务的用例必须同时写"依赖正常"与"依赖失败/降级"两组，依赖失败组是历年漏测的重灾区。用例中模拟依赖行为时注明模拟方式（mock/stub），保证可复现。

## 命名与存放

用例统一由测试平台管理，来源标记 AGENT 的用例表示由 DevPilot 测试 Agent 生成，评审通过前不得进入正式回归集。

## 验收标准

用例必须可执行、结果可判定。禁止"检查系统正常"这类无法判定的步骤，每步都要有可观察的预期结果。
