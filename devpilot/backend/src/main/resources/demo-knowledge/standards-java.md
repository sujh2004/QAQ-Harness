# Java 开发规范

## 空值防御（强制）

所有外部输入与远程调用返回值必须在使用前判空，推荐使用 Objects.requireNonNullElse 或显式 if 判空并抛业务异常。远程调用封装类（各类 *Client）不得以 null 表示失败，参见 API 设计规范。

违例典型：直接链式调用远程返回对象的 getter。任何 `xxx.getYyy()` 出现在远程调用结果的下一行都是 code review 必拦项。

## 异常处理

业务异常统一抛 BusinessException 携带错误码，禁止用 RuntimeException 裸抛。捕获异常后必须记日志或重新抛出，禁止空 catch。顶层兜底在 GlobalExceptionHandler，业务代码不要吞异常。

## 日志规范

日志必须带 traceId（MDC 注入）。ERROR 级别只用于需要人工介入的问题；可自动恢复的抖动用 WARN。打日志时占位符用 {}，禁止字符串拼接。异常对象作为最后一个参数传入，保留堆栈。

## 事务与数据库

事务范围最小化，禁止在事务内做远程调用。Mapper 查询必须带 limit。连接池是共享资源，任何单次查询超时不得超过 5 秒，避免长时间占用连接。

## 命名与结构

类名名词、方法名动词。一个方法不超过 80 行。工具类禁止实例化。依赖注入一律构造器注入，方便测试。
