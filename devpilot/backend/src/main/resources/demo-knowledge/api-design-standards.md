# API 设计规范

## 通用约定

所有内部服务间调用统一使用 JSON over HTTP。接口路径使用 kebab-case，字段名使用 camelCase。时间字段一律传 epoch 毫秒数，禁止传字符串。

## 响应结构

统一响应体：code（业务码，0 表示成功）、message（人类可读说明）、data（业务数据）。禁止用 HTTP 状态码表达业务错误——HTTP 只表达传输层结果，业务失败一律返回 200 加非零 code。

## 失败与降级的表达

下游依赖失败时，接口必须返回显式的失败结果对象（含错误码与原因），**禁止返回 null 或空对象表示失败**。返回 null 会让调用方无法区分"没有数据"与"查询失败"，是历年故障的高频根因。

需要降级时，响应中必须有 degraded=true 标记，并记录 WARN 日志说明降级原因，方便事后审计。

## 分页与批量

列表接口统一使用 page/size 参数，size 上限 100。批量接口单次最多 20 条，超过必须拆分提交。

## 兼容性

字段只增不改不删。新增枚举值必须保证老版本消费方可以安全忽略。破坏性变更需要双写过渡一个版本后再下线旧字段。
