# 故障复盘：优惠券降级引发空指针（2025-11）

## 故障概况

2025 年 11 月 14 日晚高峰，优惠券服务缓存节点故障，CouponClient 按降级策略返回 null。支付回调链路中 PaymentCallbackService 直接调用了返回对象的 getDiscountAmount()，抛出 NullPointerException，导致 217 笔订单支付回调失败，持续 38 分钟，定级 P1。

## 根因

两层问题叠加：其一，CouponClient 的降级策略用 null 表示"优惠券服务不可用"，调用方无法区分"无券"与"服务失败"；其二，所有调用点都没有判空。降级设计本意是保住主流程，结果把可恢复的依赖故障放大成了主流程异常。

## 当时的时间线

19:02 缓存节点不可用，coupon-service 开始对全部查券请求降级返回 null。19:03 支付回调错误率突增，日志出现大量 NPE，堆栈指向 PaymentCallbackService.applyDiscount。19:12 定位到 CouponClient 返回 null。19:21 热修复：调用点统一判空，无券按原价走。19:40 错误率归零。

## 整改措施

1. CouponClient 降级改为返回显式的 CouponUnavailableResult 对象，禁止用 null 表示失败（对应 API 设计规范"失败与降级的表达"一节）。
2. 所有远程调用返回值强制判空写入 code review 必拦项（对应 Java 开发规范"空值防御"）。
3. 补齐"依赖降级"回归用例组，覆盖有券、无券、券服务降级三种输入（对应测试规范"外部依赖的处理"）。

## 遗留风险

订单链路中仍有历史代码把 CouponClient 返回值直接链式调用，整改只覆盖了支付回调链路，其余调用点标记为技术债分期修复。排查同类问题时建议全仓库搜索对该客户端返回值的直接取值调用。
