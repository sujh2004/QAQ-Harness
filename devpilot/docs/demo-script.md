# DevPilot 演示脚本

面向答辩与站会的六幕演示，约 14 分钟（第 5 幕技能市场可按时间取舍）。每一幕都写了**做什么、说什么、失败了怎么办**。

演示的核心主张只有一句，其余都是它的证据：

> 这不是一个大模型答题器。它能说清「哪个 Agent、在什么时候、调用了哪个工具、拿到什么结果」，
> 并且这条链路全程可回放、可审计。

---

## 开演前 5 分钟

```powershell
cd devpilot
./scripts/bootstrap.ps1          # Docker 全栈；首次约 5-10 分钟
```

或者不用 Docker（更快，数据在内存里，重启即复位）：

```powershell
cd devpilot/backend
$env:DASHSCOPE_API_KEY = "<你的 key>"
mvn spring-boot:run "-Dspring-boot.run.profiles=demo,dashscope"
# 另开一个终端
cd devpilot/frontend; npm run dev
```

**开演前必须确认**（30 秒）：

- `http://localhost:8080/api/v1/health` 返回 `"status":"UP"`
- 知识库页显示 **7 份文档**（没有的话说明模型 key 没生效，见兜底）
- 浏览器开在 `http://localhost:5173`，左侧导航能看到七个入口

> **两次演示之间要复位**：demo profile 重启后端即可；Docker 用 `./scripts/bootstrap.ps1 -Reset`。

## 第 1 幕：Agent 的工作环境（1.5 分钟）

**做什么**：项目页 → 点进「订单服务演示项目」→ 项目概览。

**说什么**：

> 先看 Agent 能碰到什么。这里绑定了一个真实的本地代码仓库——注意这行「解析后的绝对路径」，
> 代码工具只能在这个目录里读，越界会被拒绝。下面是近期错误聚合：空指针 3 次、SQL 超时 2 次。
> 再看日志页，展开这条 ERROR，堆栈直接指到 `OrderService.java:86`。

**顺带打开**知识库页：

> 七份项目文档：架构说明、API 与 Java 规范、错误码、测试规范，还有两份历史故障复盘。
> 这是团队的经验，一会儿你会看到 Agent 真的会去查它。

**要点**：这些都是真实数据，不是给演示准备的假界面。

---

## 第 2 幕：简单代码问题（1.5 分钟）

**做什么**：对话页 → 输入：

> 创建订单接口在哪里？主要调用链是什么？

**说什么**（等待时看右侧轨迹）：

> 右边是实时轨迹。Supervisor 判断这只需要看代码，就只叫了代码 Agent——
> 它没有为了显得全面去翻日志。代码 Agent 先 `searchCode` 定位，再 `readCodeFile` 读那几行。
> 每个工具调用的耗时都在上面。

**预期**：约 50 秒，答复给出 `OrderController` → `OrderService` → `CouponClient` / `OrderMapper` 的调用链，带文件路径与行号。

---

## 第 3 幕：完整故障诊断（4 分钟，压轴）

**做什么**：新建会话 → 输入：

> 订单服务最近为什么频繁出现 500？结合历史故障给出修复建议和回归测试。

**说什么**（分三段，跟着轨迹讲）：

1. **日志 Agent 先动**：「它自己决定先查日志，找到 3 次 NPE，堆栈指向 `OrderService.java:86`。」
2. **代码 Agent 接手**：「注意 Supervisor 把行号作为线索传给了代码 Agent——第二次调用带着第一次的结论。它读到第 85 行取值、第 86 行直接调用，中间没有判空。」
3. **知识库 Agent**：「这一步是关键。它翻到 2025-11 的复盘，发现**同一个模式已经导致过一次 P1 事故**，整改要求写在规范里但这段代码没落实。这是普通的代码问答给不出来的结论。」

最后念答复的结构：

> 结论、关键证据（每条都标了来源 Agent 和位置）、原因分析、修复建议，最后是**不确定性**——
> 它明确写出哪些还没有证据支撑。能说清自己不知道什么的结论，才敢拿去用。

**如果时间充裕**，再演第二套故障（换个会话）：

> 订单查询接口大量超时，日志里有 HikariPool 告警和 SQLTimeoutException，根因是什么？我们以前遇到过同类问题吗？

约 58 秒，定位到 `OrderMapper.java:20-21` 的查询没有 `LIMIT`，并命中 2026-03 的连接池复盘。**两套故障剧情走的是完全不同的证据链**。

---

## 第 4 幕：结果落库（1.5 分钟）

**做什么**：测试用例页。

**说什么**：

> 刚才那轮里测试 Agent 生成的回归用例已经在这里了，标着 `AGENT` 来源。
> 每条覆盖有券、无券、券服务降级三种输入——这是知识库里《测试规范》要求的回归范围。
> 点「来源会话」可以跳回它是在哪次对话里设计出来的。

**加一句安全边界**：

> 这是全系统唯一的写操作。它要同时通过两道门：Agent 人设允许写、部署白名单允许这个工具。
> 两道门都不在模型能碰到的地方。

---

## 第 5 幕：能力可扩展，但扩展要过三道人工闸门（2 分钟，可选）

**做什么**：技能市场页。

**说什么**：

> Agent 的能力可以在运行时扩展——从一个远程市场装一个脚本包，装完就是一个新工具。
> 但下载来的代码要在这台机器上跑起来，得过三个人的决定。

演示时把三步做完：

1. **市场**：「清单只能走 HTTPS——能被中途改写的市场就是一条代码执行通道。点开可以先审阅源码再装。」点「安装」，指出记录下来的 sha256：「以后跑的就是现在看的这份。」
2. **项目启用**：先不启用，回到对话页让 Agent 用它——**Agent 的工具清单里根本没有这个东西**。「模型没法拒绝使用一个从没被展示过的东西。」再回来打开开关。
3. **会话审批**：Agent 这次能看见了，但执行被拒：`APPROVAL_REJECTED`。批准后再问一次，沙箱里真的跑起来，几十毫秒返回堆栈摘要，Agent 拿它当证据继续分析。

**顺带说沙箱**：

> 它跑在一个空环境里——模型密钥、数据库口令一个都拿不到；参数走 stdin 不进命令行；
> 每次给一个空的临时目录；超时就连整棵进程树一起杀掉。

---

## 第 6 幕：可追溯与断线续传（2.5 分钟）
**做什么**：会话与轨迹页 → 展开事件流。

**说什么**：

> 这是刚才那轮对话的原始事件流。turn、step、agent run、tool call 全部成对出现，
> 每条带序号。**这不是日志，是运行事实的唯一来源**——聊天记录、Agent 树、审计报表、
> 刚才那个实时轨迹，全都是从它投影出来的。

**当场演一次断线**（这一下最有说服力）：

1. 回到对话页，问一个问题，等轨迹开始滚动
2. **按 F5 刷新页面**
3. 页面重建出完整历史，并**自动接着往下滚**

> 刷新不是重新请求模型——turn 还在服务端跑。前端带着它已有的最后一个序号重连，
> 服务端只补发缺的那几条。不重复、不丢失。

**收尾**：

> 所以这套系统给的不是一个答案，而是一条可以复查的证据链。

## 兜底预案

| 现象 | 原因 | 当场怎么办 |
|---|---|---|
| 知识库页 0 份文档 | 模型 key 未生效，embedding 不可用 | 检索会明确报「未配置 embedding 模型」而不是假装成功。改用第 1、2、5、6 幕（不依赖知识库） |
| 对话报「No chat model is configured」 | `dashscope` profile 没激活或 key 失效 | 用 `curl` 直接验 key；实在不行改讲会话页的历史事件流，那是离线数据 |
| 模型很慢（>2 分钟） | DashScope 排队 | 讲轨迹：「工具调用都是毫秒级，慢的是模型推理」——这是实测结论，见测试报告第 4 节 |
| 端口 8080 被占 | 上次的进程没退 | `netstat -ano \| findstr :8080` 找到 PID，`taskkill /PID <pid> /F` |
| 演示数据看起来是旧的 | 日志时间锚定当前时刻，不会过期 | 直接重启后端复位 |

## 常见提问的答法

**「这和直接问 ChatGPT 有什么区别？」**
它读的是你的代码、你的日志、你的历史复盘。第 3 幕那条「2025-11 已经发生过一次」的结论，
不在任何公开模型的训练数据里。

**「怎么保证它不是编的？」**
每条结论都带来源与位置，而且整条链路留在事件流里可以逐条复查。第 6 幕演的就是这个。
知识库检索不到时，工具会明确告诉模型「知识库中没有」，而不是留白让它自己补。

**「Agent 会不会乱改代码？」**
代码工具全部只读，连修改代码的工具都没有。唯一的写操作是保存测试用例，且有两道门。

**「安全边界做了什么？」**
路径穿越两次校验、敏感文件按文件名黑名单拒绝、Skill 脚本在空环境沙箱里跑且拿不到任何凭据。
这些都有测试——其中路径黑名单那条，当初就是测试先抓出来的真实漏洞。
